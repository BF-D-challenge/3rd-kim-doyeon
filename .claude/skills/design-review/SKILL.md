# 모디 디자인 리뷰

`docs/design-system.md`를 **유일한 기준 문서**로 삼아 UI를 점검하고 고친다.

## 반드시 지킬 것

1. **작업 전에 `docs/design-system.md`를 읽는다.** 기억으로 하지 않는다.
2. **진단 먼저, 수정은 그다음.** 리포트를 내고 사용자가 고를 때까지 코드를 건드리지 않는다.
3. **추상적인 표현 금지.** "간격이 어색해요" ❌ → "`app/create/page.tsx:219` 카드 내부 `gap-1`(4px)이라 힌트 텍스트가 라벨에 붙어 보임. `gap-2`로" ✅
4. **우선순위를 반드시 매긴다.** Critical / Should fix / Nice to have.
5. **덜어내는 쪽을 먼저 검토한다.** 추가 제안 전에 "이거 없애면 되는 거 아닌가"를 확인한다.

---

## 진행 순서

### 1단계 — 범위 확인

무엇을 볼지 사용자에게 확인한다. 화면 하나인지, 플로우 전체인지, 특정 컴포넌트인지.
범위가 명확하면 묻지 말고 바로 2단계로 간다.

### 2단계 — 설계 의도 확인

문제를 지적하기 전에 **왜 그렇게 만들었는지** 먼저 묻는다.
의도가 있는 선택을 "틀렸다"고 하지 않는다. 다만 의도가 없으면 그것도 발견 사항이다.

### 3단계 — 5레이어 점검

| 레이어 | 보는 것 |
|---|---|
| **1. UX 전략** | 이 화면이 해결하려는 문제가 명확한가? 유저 멘탈모델과 맞는가? 게스트 무마찰 원칙을 깨지 않는가? |
| **2. 정보 구조** | 계층·그루핑·우선순위가 논리적인가? 화면당 primary 액션이 1개인가? |
| **3. 인터랙션 & 마이크로 UX** | default / loading / empty / error 4상태가 다 있는가? pressed 피드백, 포커스 플로우, 전환 타이밍은? |
| **4. 일관성** | semantic 토큰만 쓰는가? 타이포·간격·radius가 시스템 안에 있는가? 테마 accent와 앱 크롬이 섞이지 않았는가? |
| **5. 비즈니스 임팩트** | 이 수정이 무엇을 움직이는가? (초대장 생성 완료율 / RSVP 전환율 / 공유율) 움직이는 게 없으면 우선순위를 낮춘다 |

### 4단계 — 기계적 체크

`docs/design-system.md` 7장 체크리스트를 그대로 돌린다. grep으로 확인 가능한 항목:

```bash
grep -rn "min-h-screen" app components          # → min-h-dvh
grep -rn "text-xs\|text-\[1[0-2]px\]" app components   # → 13px 이상
grep -rno "#[0-9a-fA-F]\{6\}" app components --include=*.tsx  # → semantic 토큰
grep -rn "h-10\|h-11" components/ui              # → 터치 타겟 44px
grep -rn "safe-area-inset" app components        # → 하단 고정 요소에 필수
```

### 5단계 — 리포트

```markdown
## 리뷰: [화면명]

### Critical — 지금 고쳐야 함
1. **[제목]** `파일:줄`
   - 문제: (관찰된 사실)
   - 왜: (유저에게 무슨 일이 생기는지)
   - 수정: (구체적인 코드 방향)

### Should fix
...

### Nice to have
...

### 확인이 필요한 것
- (의도를 물어야 판단 가능한 항목)
```

### 6단계 — 수정

사용자가 고른 항목만 고친다.

- **토큰 변경은 `app/globals.css` / `tailwind.config.ts`에서만.** 개별 화면을 돌며 고치지 않는다
- 수정 단위를 좁게. 한 항목 = 한 커밋
- shadcn 컴포넌트는 원본 variant 구조를 유지하고 `className`으로 확장
- 수정 후 체크리스트 해당 항목을 다시 돌려 확인한다

## AI 결과물에 대한 태도

이 스킬이 제안한 수정을 그대로 통과시키지 않는다.
사용자에게 **"이 중 무엇이 실제로 유저를 막고 있다고 보나요?"**를 묻고,
근거 없이 전부 적용하려 하면 한 번 붙잡는다.

체크리스트를 다 통과한 화면이 좋은 화면인 건 아니다.
체크리스트는 바닥을 막는 도구지 천장을 올리는 도구가 아니다.
